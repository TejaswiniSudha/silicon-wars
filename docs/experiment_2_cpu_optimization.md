# Experiment 2: CPU Instruction Optimization (-O0 vs -O3)

## 1. Objective
To compare the assembly instructions generated by GCC at optimization levels -O0 and -O3 and understand how compiler optimization affects CPU instruction generation.

## 2. System Configuration
- OS: Ubuntu 26.04 (WSL2)
- Processor: AMD Ryzen 9 8940HX
- Compiler: GCC 15.2.0
- Architecture: x86-64

## 3. Experimental Files
- first_O0.s: Assembly generated using -O0.
- first_O3.s: Assembly generated using -O3.

## 4. Observations

### O0 (No Optimization)
- Uses a conventional stack frame with RBP.
- Allocates 32 bytes of stack space.
- Loads input values into separate registers.
- Stores the intermediate sum in memory.

### O3 (High Optimization)
- Removes the conventional RBP-based stack frame.
- Allocates 24 bytes of stack space.
- Uses a memory operand directly during addition.
- Avoids separately storing the intermediate sum.

## 5. Instruction Count

| Optimization | Instruction Lines |
|---|---:|
| O0 | 32 |
| O3 | 24 |

Reduction = ((32 - 24) / 32) * 100 = 25%

## 6. Conclusion

The experiment demonstrates how GCC optimization changes the assembly code generated for the same C program. The O3 version uses fewer instruction lines and a different approach to stack and register management.

This shows that compiler optimization can reduce unnecessary operations and improve code efficiency. However, instruction count alone does not establish actual execution speed.
