# Silicon Wars: Inside the CPU vs GPU Architecture

## Project Overview

Silicon Wars is a practical exploration of CPU and GPU architecture, compiler optimization, CUDA programming, and parallel computing.

The project investigates how compiler optimization affects CPU instruction generation and execution time, and how GPUs perform compared with CPUs on parallel workloads. It also includes a Python-based conceptual simulation to visualize workload distribution across CPU cores and GPU Streaming Multiprocessors (SMs).

## Experiments

### 1. CPU Instruction Optimization

Compared assembly code generated by GCC using two optimization levels:

- `-O0`: Compiler optimization disabled.
- `-O3`: High-level compiler optimization enabled.

| Optimization | Assembly Instruction Lines |
|---|---:|
| -O0 | 32 |
| -O3 | 24 |

The optimized version contained 25% fewer instruction lines in the examined assembly output. Instruction count alone does not establish execution speed.

Detailed report: `docs/experiment_2_cpu_optimization.md`

### 2. CPU Execution Time Benchmarking

Measured the execution time of a C program that calculates the sum of integers from 0 to 1,000,000,000.

Each optimization version was executed three times.

| Optimization | Average Execution Time |
|---|---:|
| -O0 | 1.3002 seconds |
| -O3 | 0.5273 seconds |

**Observed speedup: 2.47x**

The `-O3` version reduced average execution time by approximately 59.44%, while both versions produced the same final sum.

Detailed report: `docs/experiment_3_cpu_benchmark.md`

### 3. CPU vs GPU Performance Benchmarking

Two parallel computing workloads were implemented using CUDA and compared with CPU implementations.

**Vector Addition**
- Input size: 10 million elements.
- Operation: `C[i] = A[i] + B[i]`.
- Verified output: `4`.

**Matrix Multiplication**
- Matrix dimensions: 512 × 512.
- Operation: `C = A × B`.
- Verified first output element: `1024`.

#### Recorded Results

| Experiment | CPU Time (ms) | GPU Time (ms) | Speedup |
|---|---:|---:|---:|
| Vector Addition | 5.84 | 4.94 | 1.18x |
| Matrix Multiplication | 129.78 | 6.38 | 20.34x |

The matrix multiplication experiment showed a larger GPU advantage because its workload offers more opportunities for parallel execution. Vector addition showed a smaller advantage because each element requires relatively little computation.

**Timing note:** CPU timings cover computation loops. GPU timings cover kernel launch and device synchronization, excluding memory allocation and host-device data transfers. These figures compare computation timings rather than complete end-to-end execution times. Results may vary with system conditions.

Detailed report: `docs/cpu_gpu_comparison.md`

### 4. CPU vs GPU Architecture Simulation

Developed a Python-based conceptual simulation to visualize how independent work units can be distributed across CPU cores and GPU Streaming Multiprocessors.

The model uses:
- 16 CPU cores, assigning one work unit per core per round.
- 20 GPU SMs, assuming four concurrent blocks per SM.
- A total modeled GPU capacity of 80 work units per round.

#### Simulation Results

| Work Units | CPU Scheduling Rounds | GPU Scheduling Rounds |
|---:|---:|---:|
| 160 | 10 | 2 |
| 320 | 20 | 4 |
| 640 | 40 | 8 |

**Important:** This is a conceptual scheduling model, not a cycle-accurate hardware simulation. The assumed GPU block capacity is a modeling choice, not a measured hardware occupancy limit. Scheduling rounds do not represent actual execution time or measured speedup.

Detailed methodology: `docs/cpu_gpu_simulation_report.md`

## How to Run

### Requirements

- GCC compiler
- NVIDIA CUDA Toolkit and `nvcc`
- Python 3
- NumPy and Matplotlib
- CUDA-compatible NVIDIA GPU for GPU experiments

### Compile and Run CPU Programs

```bash
gcc -O0 cpu/first_program.c -o cpu/first_program
./cpu/first_program
```

Compile and run the CPU benchmark:

```bash
gcc -O0 cpu/cpu_benchmark.c -o cpu/cpu_benchmark_O0
./cpu/cpu_benchmark_O0

gcc -O3 cpu/cpu_benchmark.c -o cpu/cpu_benchmark_O3
./cpu/cpu_benchmark_O3
```

### Compile and Run GPU Programs

```bash
nvcc gpu/first_gpu.cu -o cpu/first_gpu
./cpu/first_gpu
```

### Run CPU vs GPU Benchmarks

```bash
nvcc -O3 benchmarks/cpu_gpu/vector_add.cu -o benchmarks/cpu_gpu/vector_add
./benchmarks/cpu_gpu/vector_add

nvcc -O3 benchmarks/cpu_gpu/matrix_multiply.cu -o benchmarks/cpu_gpu/matrix_multiply
./benchmarks/cpu_gpu/matrix_multiply
```

### Run the Architecture Simulation

```bash
cd simulation
python3 architecture_simulation.py
```

### Generate Performance Graphs

```bash
cd benchmarks/cpu_gpu
python3 plot_results.py
```

The plotting script uses recorded benchmark measurements to generate comparison graphs in the `docs/` directory. It does not execute the benchmarks automatically.

## Key Takeaways

- Compiler optimization can substantially change generated assembly and CPU execution time.
- Instruction count alone is not a reliable measure of performance.
- GPUs can accelerate workloads with substantial parallelism.
- GPU launch and data-transfer overhead matter when evaluating real application performance.
- Conceptual architecture simulations help explain scheduling but should not be confused with measured hardware performance.
